Drag & Drop

Fresh off Animation, let's pick up a different kind of interactivity: moving data around by dragging it.

Drag-and-drop transfers data between two Views, or between a View and something outside your app entirely. The Views involved can live in the same app, in separate apps, or the whole operation can start or end in a third-party app you have no control over at all. Three pieces make this work: a DragRecognizer on the source View, a DropReceiver on the target, and a DataBundle carrying the payload between them. Either end can be external, so it's entirely possible for a recognizer or receiver to be missing from the picture.

Here's the operation in a nutshell: someone presses and drags within a source, drags that pointer onto a target, and releases. Data gets captured from the source and handed to the target, which decides whether — and how — to accept it.

Module Required

Include the DragDropModule (Web, Desktop) in your application to use these features.

package dragdrop import io.nacular.doodle.application.Modules.Companion.DragDropModule import io.nacular.doodle.application.application import org.kodein.di.instance import rendering.MyApp fun main() { //sampleStart application(modules = listOf(DragDropModule)) { MyApp(instance(), instance()) } //sampleEnd }
tip

The DragDropModule imports the PointerModule (Web, Desktop) as well, so you do not need to do so.

Data bundles​

Before we get to sources and receivers, it's worth meeting the thing that actually moves between them. A DataBundle manages the data being transferred, and it's a small interface — really just two methods, both keyed by MimeType:

  • contains — does the bundle have data of this type?
  • get — hand it over.

Keep this in your back pocket — you'll see event.bundle checked and read this exact way throughout the examples below.

Creating a source​

Attach a DragRecognizer to any View to make it a drag source. The recognizer's job is deciding when a drag PointerEvent should kick off an operation — implement the interface yourself, or reach for the dragRecognized DSL for the common case:

package dragdrop import io.nacular.doodle.datatransport.dragdrop.DragOperation import io.nacular.doodle.datatransport.dragdrop.DragRecognizer import io.nacular.doodle.datatransport.dragdrop.dragRecognized import io.nacular.doodle.event.PointerEvent //sampleStart // Interface approach class Custom: DragRecognizer { override fun dragRecognized(event: PointerEvent): DragOperation? { TODO("Not yet implemented") } } // DSL approach val recognizer = dragRecognized { _: PointerEvent -> TODO("Not yet implemented") } //sampleEnd

The operation begins the moment a recognizer hands back a non-null DragOperation. That object carries the transfer data, the user's intended action (copy, move, link), and the visual shown as feedback during the drag. It sticks around for the operation's whole lifecycle, getting notified when dragging starts, completes, or gets canceled, so the source can react to how things turned out.

Receiving drops​

Attach a DropReceiver to any View to let it catch drops. Drag a pointer over a View with a receiver, and it fires dropEnter; keep moving, and you'll get dropOver or dropExit; release, and drop fires. Every one of these hands you a DropEvent describing the data in transit and the user's intended action.

The DropReceiver signals whether the current operation is welcome by returning true from any of these — or false to turn it away.

package io.nacular.doodle.docs.apps import io.nacular.doodle.application.Application import io.nacular.doodle.controls.buttons.PushButton import io.nacular.doodle.core.Display import io.nacular.doodle.datatransport.PlainText import io.nacular.doodle.datatransport.dragdrop.DropEvent import io.nacular.doodle.datatransport.dragdrop.DropReceiver import io.nacular.doodle.docs.utils.DEFAULT_FONT_FAMILIES import io.nacular.doodle.docs.utils.DEFAULT_FONT_SIZE import io.nacular.doodle.drawing.Color.Companion.White import io.nacular.doodle.drawing.FontLoader import io.nacular.doodle.drawing.paint import io.nacular.doodle.geometry.Size import io.nacular.doodle.layout.constraints.center import io.nacular.doodle.layout.constraints.constrain import io.nacular.doodle.theme.Theme import io.nacular.doodle.theme.ThemeManager import kotlinx.coroutines.CoroutineScope import kotlinx.coroutines.Dispatchers import kotlinx.coroutines.SupervisorJob import kotlinx.coroutines.launch class ButtonDropApp( display : Display, fonts : FontLoader, themeManager: ThemeManager, theme : Theme ): Application { init { CoroutineScope(SupervisorJob() + Dispatchers.Default).launch { val font = fonts { families = DEFAULT_FONT_FAMILIES size = DEFAULT_FONT_SIZE } themeManager.selected = theme //sampleStart val button = PushButton("_____").apply { this.font = font suggestSize(Size(80, 40)) dropReceiver = object: DropReceiver { override val active = true private fun allowed (event: DropEvent) = PlainText in event.bundle override fun dropEnter (event: DropEvent) = allowed(event) override fun dropOver (event: DropEvent) = allowed(event) override fun dropActionChanged(event: DropEvent) = allowed(event) override fun drop (event: DropEvent) = event.bundle[PlainText]?.let { this@apply.text = it; true } ?: false } } //sampleEnd display += button display.layout = constrain(display.first(), center) display.fill(White.paint) } } override fun shutdown() {} }

This one accepts PlainText and assigns it straight to the button's own text — drag some text onto it, or even drag straight from the button in the previous example.

tip

A single View can be a source and a target at the same time — nothing stops it from wearing both hats.

The full sequence​

Put a source and a receiver together, and here's the order things actually happen in, end to end:

  1. The user presses and drags a pointer within a source View. Its DragRecognizer returns a DragOperation, and the operation begins.
  2. As the pointer crosses onto a View with a DropReceiver, that receiver gets dropEnter.
  3. Further movement within that View fires dropOver; changing the requested action (holding a modifier key, say) fires dropActionChanged; leaving without dropping fires dropExit.
  4. Releasing the pointer over a receiver that's still willing fires drop — this is where the receiver actually reads the bundle and acts on it.
  5. Back on the source side, the DragOperation hears about how things ended: completed(action) if the drop succeeded, or canceled() if it didn't.

That last step is exactly what lets ButtonDragApp above clear its own text only when the action was Move — the source finds out the outcome and reacts accordingly.

Handling files​

Drag-and-drop covers file transfer too, through the very same DropReceiver mechanism — just with the Files mime-type marking which file types are welcome. Since Files hands back a whole collection at once, a single receiver can happily deal with several dropped files in one go.

Try dragging files onto the table below — it only accepts the types currently selected in the list beside it.

Recap​

  • Three pieces make up an operation: a DragRecognizer on the source, a DropReceiver on the target, and a DataBundle carrying the data — either end can be external to your app entirely.
  • Check and read a bundle with contains/get, both keyed by MimeType.
  • A DragOperation lives for the whole operation, so the source can react to whether it completed or was canceled.
  • Events fire in order: dropEnter → dropOver/dropActionChanged/dropExit → drop on the receiver, then completed/canceled back on the source.
  • Files drop through the same DropReceiver mechanism, using the Files mime-type.
